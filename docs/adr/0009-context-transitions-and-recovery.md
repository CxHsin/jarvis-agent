# 活上下文转换与恢复边界

#36 把版本 2 的请求回退明确记录为 `context_rollback`：同条事件记录可见边界与保留的运行时状态，无工具开始执行的失败退出活上下文，其原始消息、压缩和审计仍留在日志。投影回退只影响对话与证据上下文，权限状态、权限审计和供应商回退独立保留；权限变更及审计同条提交，避免恢复停在审计与状态之间时重新扩大权限。此决策接替 ADR 0008 的 `context_reset` 兼容桥，替代 ADR 0003 的物理截断；旧桥仍可读，版本 1 自动迁移由 #37 处理。

任务终态与上下文有效性分开：工具开始后的模型失败记为 failed 但保留结果、审计及活上下文；取消记为 cancelled，保持工具消息配对。缺失结果沿用 ADR 0007 的执行状态未知占位，恢复绝不重跑工具。Recent 的最小适配读取上下文有效性，完整 History/Recent/Pending 派生仍属于 #41。

消息及压缩先提交记录再更新内存。已提交的 checkpoint 是活上下文的依据，后续任务不能用 Recent 中完整的退休原文覆盖它；Recent 仍保存近期完整轨迹，压缩后的上下文继续由同一预算线控制。自动、主动与溢出恢复沿用 ADR 0005 的同一服务、合法切点、单条累积 checkpoint 与至多一次溢出重试。提交失败不提前展示未提交的压缩结果；提交后进程退出则从事件恢复。原始事件已提交后的派生写入错误只报告待重建，不撤销提交成功；再次读取或更新派生视图前从原始记录重建，避免调用方把已提交转换误当成失败。代价是读取上下文需检查当前事件投影，投影性能的测量与完整派生重构留在后续任务。
