# 旧会话的可重试迁移与来源保护

#37 在首次恢复版本 1 会话时自动迁移，沿用会话锁。旧会话和轨迹保留原路径与原字节；新事件位于该工作区会话目录的 `migrations/<会话标识>/events.jsonl`，`committed.json` 是唯一切换标记，包含逐行来源映射、警告及冲突。列出会话读取已提交的新记录，之后追加只写新事件。没有提交标记时旧会话仍可列出，重试从不可覆盖的备份重新构建候选。

迁移先以 SQLite backup API 保存 Memory DB 的一致性快照（包含 WAL 中已提交内容），不用文件复制代替数据库备份。应用创建记忆服务前，发现旧会话且已有 Memory DB 时，先保存 `STATE_DIR/migrations/legacy-memory/` 中的数据库和人工 Markdown；它先于画像恢复、发布等启动行为。每个会话的 `backup/` 另保存原会话、轨迹及迁移时数据库快照。SQLite 备份与并发事务使用数据库自身的快照边界；迁移不修改事实表或来源表，不重新提取，保留身份、有效期、修正、忘记记录及画像版本。旧来源路径仍可解析，提交报告把原路径、原行号、原事件/任务标识映射到新事件；非轨迹的用户操作及画像编辑来源不改写。缺失来源保留并报告。

旧日志与轨迹曾分步写入，没有共同身份可证明同一发生事件；即使文本相同也不合并。导入保持各来源内部顺序，不以时间戳猜测两份日志的交错顺序。会话流继续决定活上下文、压缩、工具配对和运行时状态；轨迹流继续决定 Recent 与完整原始证据，包含已从会话物理回滚的失败任务。事件的 `migration_projection` 明示这两个既有读取语义，普通新事件没有此标记。重复事件身份分配稳定替代身份，来源映射保留旧身份并报告冲突。此处选择完整保留和显式报告，完整派生重构留给 #41。

备份目录、候选事件文件、提交标记分别以同卷原子重命名发布，文件发布前 fsync。备份已发布后不覆盖；任一发布前退出可重试，提交标记发布后只读取已验证的新事件。验证比较旧与候选的恢复内容（含工具消息、归档、压缩引用、权限和审计），校验事件身份、提交顺序及来源关系。截断尾记录的原始字节留在备份并报告；中间损坏记录拒绝切换。新事件缺失或提交标记损坏时拒绝退回过期旧日志。提交之后派生视图失败明确报告“迁移已经提交”，下次恢复重建派生视图。

固定样本位于 `tests/fixtures/legacy/`；迁移测试使用临时真实存储，覆盖压缩、工具结果、物理回滚残留、冲突、半条尾记录、事实修正及忘记、来源、画像版本、WAL 和每个会话迁移 fsync/发布边界的进程退出。这里保证进程中断重试；文件系统与硬件是否兑现掉电持久性仍取决于运行平台。
