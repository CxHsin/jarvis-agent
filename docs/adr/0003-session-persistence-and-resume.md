# 会话记录持久化与显式恢复

Jarvis 把模型可见的消息、任务边界、工具结果归档和上下文改写按发生顺序写入单个会话的 JSONL 事件日志：每条记录写穿落盘，模型请求失败时把文件截断回请求开始的位置，并在内存里还原同一状态，因此进程被杀最多丢失正在写的那一条记录。状态目录默认位于工作区之外，按工作区路径分目录，`STATE_DIR` 可覆盖，避免 Jarvis 自己的文件工具读到自身的记录文件。每次启动默认新建会话，续接必须显式 `--resume`：不带参数取本工作区最近一段，`--list` 列出候选。加载时按顺序重放消息并套用压缩改写，从归档记录重建证据索引，对缺少结果的工具调用补写「中断未执行」的占位结果而不重新执行；同一会话同时被两个实例恢复时，第二个实例被会话锁拒绝。

选择这一方案是为了让中断与重启不再丢失对话状态，同时保住三件既有约束：Chat Completions 的 tool 消息配对、压缩摘要里「原始内容在会话归档中」的可核对性，以及 ADR 0001 的稳定消息前缀。代价是压缩不再是纯追加，必须写成改写事件；会话文件随会话增长而增长，本轮不做自动清理。
