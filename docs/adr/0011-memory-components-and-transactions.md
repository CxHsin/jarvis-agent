# 记忆组件与事务的显式边界

#38 保留 ADR 0006 的原始证据与派生记忆区分，以及现有 SQLite 表、来源标识和 Markdown 格式。`MemoryService` 是公开操作与装配入口，以构造参数组合 `StableMemory`（事实准入、时间线、来源和冲突）、`MemoryRetrieval`（索引与召回）、`ProfileMemory`（画像版本、人工编辑和发布）与 `PendingMemory`（提取、晋级、调度和 worker 生命周期）；组件不再通过继承顺序或共享宿主私有字段协作。事实组件只接收一个在当前连接内更新关键词索引的函数，不依赖检索配置或后台状态。

`MemoryStore` 独占连接创建、扩展加载、关闭、进程内锁及提交/回滚责任。只读操作使用禁止写入的 SQLite 快照；写操作在读取决策状态前取得 `BEGIN IMMEDIATE`，组件通过显式传入的连接参与同一事务，不自行提交或嵌套写事务。模型提取、分类和 embedding 调用均在事务之外。SQLite 写锁继续协调不同服务实例/进程；进程内可重入锁还保护文件发布和 worker claim 状态。

记住操作原子保存事实、来源、冲突、关键词索引与幂等操作记录，画像仍推迟到 consolidation。修正、忘记和 Pending 晋级在画像可发布时，将这些变化与画像版本、发布 outbox 放入同一事务，避免画像写入失败却留下半次操作；Pending 原始提取批次可以先独立提交，失败后仍可重试晋级。发布时机保持为已完成的提取批次或成功的 consolidation；空轮询及失败分类不会提前发布此前 remember 的画像。人工画像编辑的事实变化和版本/outbox 同样原子提交。发布器只在提交后替换 `memory.md`，随后另事务确认 outbox；文件发布或确认中断时，已提交事实不会回滚，启动/后续画像操作可恢复。这刻意不把 SQLite 与文件替换声称为一个原子事务。

若文件含尚未导入的人工修改，修正/忘记与后台晋级保留其事实决定并推迟画像发布；文件不会被生成内容覆盖。中断后出现更新的人工修改仍须保留编辑、恢复已提交画像，再通过任务入口导入修正。关键词与向量召回继续从 DB 读取，保留来源、有效期过滤、忘记证据抑制、8 条/1,000 token 动态预算和 1,500 token 画像预算。向量后台补建属于 #39，本次不改变其前台同步路径。

`tests/test_memory_transactions.py` 通过公开操作和真实 SQLite `RAISE(ABORT)` 触发器验证操作记录、画像版本及 outbox 写入失败后的原子性、重启和幂等重试；Agent 工具入口覆盖修正失败、错误结果及重试。既有事实、Pending、召回、权限、画像导入和发布确认中断测试继续约束兼容行为，测试只使用临时合成数据与受控客户端。
