# 从统一原始事件重建记忆投影

#41 让 History、Recent 与 Pending 输入共用原始事件和任务窗口规则，接替 ADR 0008–0010 中留待本任务完成的派生桥。History 按 task 事件中的原始用户输入生成每日索引，保留失败输入及任务/事件身份和完整来源路径；不把 assistant、工具结果、checkpoint 或编辑后的 Markdown 当作用户陈述。新会话不另写轨迹文件，Recent 上下文切换只保存原始 message 事件 ID；旧的正文型 recent_context 仍可读取。checkpoint 继续由会话上下文投影负责，Recent 的完整轨迹不能替换它。

正常任务与恢复共用 TaskHistory 的任务折叠：保留在途任务和最近 N 个上下文有效的已结束任务。无工具失败及 rollback 排除的任务不占窗口；工具已开始后的 failed、cancelled 和 interrupted 继续遵守 ADR 0007/0009 的证据保留规则，但只有 completed 且移出窗口的任务进入提取队列。后台恢复按最后任务保存的窗口扫描全部工作区的已提交统一记录，也读取尚未迁移的旧轨迹；已迁移会话跳过旧轨迹副本，保留 migration_projection 的双流语义。不改写旧备份、来源映射、现有批次来源或独立迁移入口。

`MemoryService.rebuild_projections()` 是无模型调用的修复入口；启动提取 worker 时也执行恢复。History 在任务输入和恢复时重建，Recent 随任务消息与有效性变化发布。进程内锁串行化共享 Markdown 发布；文件替换只发布派生结果。会话先提交原始事件，再更新内存折叠和文件/队列；发布持续失败时报告待重建，前台仍使用已提交事件形成的状态，原始读取失败则不以旧状态冒充成功。损坏、删除或编辑这些 Markdown 不改变证据、checkpoint 或 Memory DB 中人工修正和忘记决定。

Pending 沿用 task_id 唯一批次、事件 ID 来源集合和数据库 claim/结果事务。重复重建不会重置已提取批次；结果已提交但 Markdown 发布失败，重启只重建文件，不再次调用提取模型。提取失败或进程在结果提交之前退出仍可重试，不能承诺远端模型调用恰好一次；已提交结果及候选来源不会重复写入。原始事件全量扫描的规模测量留给 #42/#43，不引入第二份原始事实或新的记忆权限。
