# 新会话使用统一只追加事件记录

#35 为新会话引入版本 2 会话记录：沿用每会话 JSONL 路径，由 SessionStore 在同一写锁下分配身份、顺序并写穿落盘，任务轨迹与恢复读取同一份原始事件。选择逐会话扩展而不是重写既有数据，以避免会话日志与任务轨迹分步写入、身份分叉，同时保留已有来源、会话锁和旧格式读取。

每条事件包含 `event_version=1`、随机且持久不变的 `event_id`、`session_id`、从 1 开始递增的 `sequence`、UTC `recorded_at` 和可空的 `occurred_at`。任务开始分配独立 `task_id`，后续消息、工具执行审计、原始结果、上下文变化与终态沿用该身份；任务外记录关联最近任务，尚无任务时为空。工具调用仍通过消息、归档和审计中的 `call_id` / `tool_call_id` 关联。上下文任务计数可以因失败回退，不能当作原始任务身份。顺序由提交序号决定，不以时间戳排序；落盘成功后才更新 History、Recent 与 Pending 的既有派生入口，它们不另造新事件身份。

新格式替代 ADR 0003 的物理截断：既有请求回滚入口追加 `context_reset`，以 `through_sequence` 指明恢复到的可见记录边界，原始消息及压缩事实仍在。Recent 同时把该边界之后的任务视为失败，即使进程在写入终态前退出也不会重新注入失败输入。此处仅提供旧请求协调流程所需的兼容桥；失败、取消、权限和压缩投影的整体收敛属于 #36，History/Recent/Pending 的完整派生重构属于 #41。本阶段保留 ADR 0005 的压缩入口与 ADR 0007 的副作用、未知结果及权限规则。

恢复忽略无法解析的半条尾记录并报告，下一次追加先补换行而不删除原始字节；已提交事件的身份与序号不会改变，缺失工具结果补写执行状态未知且不重跑工具。旧版本 1 仍使用原会话及轨迹读取和写入路径；自动迁移、来源映射、备份及迁移切换属于 #37，本阶段不改写真实旧历史或 Memory DB。格式不支持时拒绝打开，避免用旧程序解释未来会话。代价是新旧路径暂时共存，派生视图的完整断点修复仍需后续任务；原始事件始终先于派生写入。
